# 短视频自动剪辑全流程操作手册

Windows 环境搭建与 Bloom10 英语口播案例

版本日期：2026年10月27日。项目目录：F:\VideoAutomation。适用对象：Leo 与后续维护人员。

本手册记录这次从空目录搭建环境，到完成第一条英语口播视频的实际过程，并提供重建和复用方法。阅读顺序是环境、工程、转录、字幕、分镜、效果、声音、渲染和验收。已经配置好的电脑，日常制作可以直接从素材导入开始。

第一条完整视频已经导出，自动检查通过。如果你完整看过视频，确认字幕内容与同步、画面、声音和节奏都没有修改意见，这个版本就可以作为成片交付，无需为了完成制作而再做一轮渲染。

## 二 各个工具负责什么

本方案部署在本机。Remotion保存主时间轴并输出最终MP4；HyperFrames只制作独立效果，再交给Remotion合成。转录和媒体处理也在本机运行。

| 工具或文件 | 具体用途 |
| --- | --- |
| Remotion | 用React和TypeScript组织画面、字幕、图形与最终视频 |
| HyperFrames | 用HTML与可定位时间轴生成独立标签等效果 |
| whisper.cpp | 从音频识别原文和估计时间信息 |
| FFmpeg与FFprobe | 音频提取、工作画面生成、编码、规格及音量测量 |
| Chrome | 预览和逐帧渲染网页画面 |
| Git | 保存代码、配置和文档的版本历史 |
| brand/BRAND.md | 记录当前视频的颜色、字体、布局和声音规则 |
| scripts目录 | 保存转录、准备媒体、渲染辅助及检查脚本 |

原帖提到的Google Drive remotion-reel技能包，本次没有下载或验证。实际使用的是项目脚本、工作样式，以及HyperFrames安装包中的本地制作和CLI技能。人像抠图、标题置于头后、录屏鼠标跟随和复杂3D效果，都没有在本条视频中制作。

这意味着当前工程已经跑通一条真实视频的制作链路，但并非原帖列出的全部效果都已安装或测试，也不是放入任意素材就能无人确认地生成最终广告。

## 六 编译 whisper.cpp 并准备模型

### 编译本地识别程序

第一次完整克隆因历史传输缓慢而中止，后来使用浅克隆成功。下面给出可固定到本次提交的重建方式。已有bin/whisper.cpp目录时不要再次clone覆盖它。

```powershell
Set-Location F:\VideoAutomation
git -c http.version=HTTP/1.1 clone --depth 1 `
  https://github.com/ggml-org/whisper.cpp.git bin/whisper.cpp
git -C bin/whisper.cpp fetch --depth 1 origin `
  231638a0717b7822784297e5980965ffcec05810

  -DGGML_CUDA=OFF -DGGML_VULKAN=OFF
cmake --build bin/whisper.cpp/build --config Release `
  --target whisper-cli --parallel 4
```

本次程序版本为1.9.5-dev，使用CPU和AVX2。程序位于bin/whisper.cpp/build/bin/Release/whisper-cli.exe。请保留同目录DLL，不能只拷贝exe。源码与构建说明见[whisper.cpp官方仓库](https://github.com/ggml-org/whisper.cpp)。

## 七 导入素材并检查身份

当前英语素材的准确位置是public/recordings/Bloom10/Bloom10-达人素材.mp4，约40.26MB、30.278秒、1080×1920、标称30fps，HEVC画面与AAC双声道音频。

```powershell
Get-FileHash -LiteralPath $video -Algorithm SHA256
```

```text
31bf76ef1375c072f53117d2379660d40973ed323d61037d34afc3786a8274c3
```

检查时确认有音轨、画面方向正常，并查看开头、中间和结尾。视频里的语言标签可能不准确，实际讲话语言需要识别或听校。后续制作不同视频时，优先给素材使用不同文件名。

## 八 转录并校对英文字幕

### 运行通用转录脚本

scripts/transcribe.mjs负责提取16kHz单声道PCM音频，调用whisper.cpp，转换结果，并保存原始音频、识别JSON和日志。默认模型是base；英语案例明确选择small.en。

```powershell
npm.cmd run transcribe -- `
  "public/recordings/Bloom10/Bloom10-达人素材.mp4" `
  --language en --model "bin/whisper.cpp/models/ggml-small.en.bin"
```

脚本默认拒绝覆盖已有结果。需要重跑时，先把public/transcripts/下该素材的五个文件复制到独立归档目录，再在命令末尾增加--force。每次原始识别运行仍会独立保存在out/transcriptions/下。

| 输出后缀 | 内容 |
| --- | --- |
| .txt | 原语言机器文字稿 |
| .json | text、startMs、endMs组成的数组 |
| .srt | 合并分段后的可读字幕 |
| .review.json | 低概率提示和人工核对说明 |
| .meta.json | 源文件指纹、模型、语言、时长和运行目录 |

JSON中的短时间单元是ASR估计。在英语中往往接近单词；中文可能是字或token。它不是人工逐词标注，也不是强制对齐结果。低概率提示不是准确率分数，未提示的词也可能有误。

### 记录人工修订

本次英语base初稿有116个时间单元；small.en有115个时间单元、14条自动SRT。对照识别让breast gummies、size container、highly recommend等表达更合理，但不能只凭模型更大就自动确认所有词。

约14秒的句子，两版分别识别成fill/go the bottle away。用户明确确认使用throw the bottle away，因此修订稿采用throw，并记录确认来源。重复I'll只在字幕显示中合并，原声未删减；gonna和y'all等口语保留。

```powershell
node scripts/prepare-bloom10-review.mjs --captions-only
```

这个脚本会生成edited.txt、edited.json、edited.srt、edited.cues.json和edited.review.json。最终显示单元114个、可读字幕18条，加入标点并按两行排版。它是本案例的专用脚本，包含固定指纹、时长和修订位置，不能用于任意新素材。

当前样式来自用户已审阅的分镜和标签样片，适用于这一条视频。不同平台界面仍需实看，并不能把本例坐标当成所有平台都适用的固定安全区。

```powershell

```

完整运行会生成修订字幕、六张原片静帧和public/storyboards/bloom10/plan.json。本次通过交互审阅页逐段选择Keep、Maybe或Drop。Drop表示取消图形，保留口播；Maybe应说明怎样修改。用户六段全部选择Keep，结果保存在review-r1.json。

| 分镜 | 原片时间 | 方向 |
| --- | --- | --- |
| 体验开场 | 0至7.60秒 | 真人与ONE WEEK IN标题 |
| 独立包装 | 7.60至10.08秒 | 强调individually wrapped |
| 粘瓶痛点 | 10.08至15.19秒 | 保留上下文和已校对字幕 |

| 推荐结尾 | 27.12秒至结尾 | 推荐字幕和SEE PRODUCT DETAILS提示 |

这一步确认的是画面方向。先用静帧确认字幕和产品位置，再做动态效果，可以避免把整条视频反复渲染后才发现布局不合适。

### 编辑效果并检查

项目位于hyperframes/packaging-label。index.html是主入口，compositions/label.html是标签场景。根时长2秒，尺寸1080×1920，帧率30。GSAP时间轴暂停后由运行时定位，每个场景注册到window.__timelines。

本地保存GSAP 3.15.0和Inter700，避免渲染时依赖在线加载。动画为0至0.32秒滑入、0.55至1.23秒光泽扫过、1.66至1.90秒淡出。效果本身无声音，方便主工程统一混音。

```powershell
Set-Location F:\VideoAutomation\hyperframes\packaging-label
npm.cmd run check -- --json --snapshots --timeout 30000
npx.cmd hyperframes@0.8.206 preview --background --port 3017
npx.cmd hyperframes@0.8.206 preview --status --json
npm.cmd run render -- --format webm --fps 30 --workers 1 `
  --quality looks --output ../../out/hyperframes/packaging-label.webm
```

预览地址是http://127.0.0.1:3017/#project/packaging-label。交给用户前确认服务在线；验收结束后运行preview --stop，关闭本项目的预览服务。本次3017预览已在标签验收后停止，需要时可重新启动。

完整检查的运行、布局、动画和对比度均无错误。首帧为空、文字停留不足独立结尾卡2秒要求的两条提示，已结合透明叠加片段用途审查：淡入淡出是预期设计。

### 验证透明输出并交给主工程

输出的VP9 WebM是1080×1920、30fps、60帧、2秒。除了alpha标签，还解码检查了像素：外部alpha为0、标签内部为255，确认是真透明。透明原件复制到public/effects/packaging-label.webm。

在Remotion中使用OffthreadVideo的transparent属性加载该文件，263帧开始、持续60帧，整体上移160px。下一个标题从323帧才开始，避免两层顶部图形重叠。本次用户先看过叠在原片上的2秒样片并确认，再接入整片。

## 十一 准备画面与混合音轨

```powershell
Set-Location F:\VideoAutomation
npm.cmd run prepare:bloom10
```

这个命令调用prepare-bloom10-first-cut.mjs，先核对素材指纹，生成909张842×1498工作画面，再准备人声、背景音、音效和混合音轨。生成媒体在public/derived/bloom10/，已被Git忽略，可以从原片和脚本重建。

最初直接逐帧解码视频的方式在本机变慢，因此改为预先生成对应画面帧。Remotion按帧号读取画面，再合成字幕、标题和透明效果。帧数、顺序和完整口播均保留；末尾按30fps取整至909帧。

原人声测得约−29.03 LUFS，经过测量和调整后约−16.05 LUFS。背景音是脚本生成的低音量合成和弦，未引用外部音乐录音；实测约−36.48 LUFS，比人声低约20 LU。263帧和515帧各加入一个短音效，主混音统一限制峰值。

| 工作文件 | 用途 |
| --- | --- |
| frames/frame-0000.jpg至frame-0908.jpg | 与时间轴对应的工作画面 |
| voice.wav | 调整后的原人声 |
| music.wav | 当前自制背景音 |
| effects.wav | 两个已定位的短音效 |
| mix.wav | 给Remotion加载的完整混合音轨 |

只改声音时运行node scripts/prepare-bloom10-first-cut.mjs --audio-only；只重建画面时使用--proxy-only。两个选项都仍然核对源文件身份。

本案例播放画面不自带第二份人声，声音单独从mix.wav加载，防止双重播放。若以后更换配乐，保留人声和音效分轨，只重做混音并复测。

## 十二 制作时间轴并导出完整视频

当前Composition名为Bloom10FirstCut，主代码在src/Bloom10/FirstCut.tsx，注册与总时长在src/Root.tsx。字幕使用修订的短单元和可读cue数据，当前讲话词以较深粉色强调。

```powershell
npm.cmd run dev
npm.cmd run lint
npm.cmd run render:bloom10 -- `
  --browser-executable="C:\Program Files\Google\Chrome\Application\chrome.exe"
```

预览中选择Bloom10FirstCut。默认本地地址为http://localhost:3000/Bloom10FirstCut，具体端口以终端为准。预览服务不运行时，链接不会打开；MP4成片仍可直接播放。

渲染命令使用2个并发任务、H.264、CRF18、veryfast编码、分开取图与编码，并把视频解码缓存限制为256MiB。实际参数保存在package.json的render:bloom10中，完整日志在out/bloom10-first-cut/render.log。

不要在渲染期间替换原片、修改正在使用的字幕文件或写入同一个输出视频。为下一版使用独立版本名，方便比较。当前文件名r1只是版本标记；若验收通过，它就可作为交付版本。

## 十三 检查成片并进行最终验收

```powershell
npm.cmd run verify:bloom10
```

验证脚本检查视频规格、909帧、音轨、最终AAC响度与峰值、素材指纹；同时导出全部18条字幕拼图、六段关键画面，并扫描排除顶部图形和字幕后的中央画面区域。

本次最终编码的综合响度约−16.04 LUFS，真峰值−1.44 dBTP。使用loudnorm测量已有文件时，应读取input_i和input_tp，它们是输入文件的实际测量值；output_i等字段是滤镜处理后的预测结果，不能混淆。

字幕排版曾出现长句越界。修正后用实际Inter700字体、58px字号和词间距测量全部字幕，最宽行约718.8px，位于800px字幕区内；随后重新渲染并再次查看导出像素。

| 检查文件 | 作用 |
| --- | --- |
| out/bloom10-first-cut/validation.json | 最终规格、音频与扫描结果 |
| out/bloom10-first-cut/caption-widths.json | 实际字体行宽测量 |
| out/bloom10-first-cut/all-caption-cues.jpg | 全部18条字幕的像素检查 |
| out/bloom10-first-cut/six-beat-contact.jpg | 六段关键画面检查 |

你最终需要完整播放视频，核对人名产品词、字幕同步、图形是否遮挡、开场节奏、音乐和声音。可按“时间点、当前问题、希望怎样改”反馈。没有修改意见时，本轮制作完成；若有意见，只调整相关部分，再做相应导出与检查。

## 十四 制作下一条视频的方法

### 可以直接复用的部分

本机工具、Remotion框架、通用transcribe.mjs、模型、字体、已确认的样式方向，以及独立效果资产可以复用。先为新素材使用独立文件名和目录，避免与当前结果冲突。

```powershell
npm.cmd run transcribe -- `
  "public/recordings/SecondVideo/SecondVideo-take01.mp4" `
  --language en --model "bin/whisper.cpp/models/ggml-small.en.bin"
```

### 必须针对新素材调整的部分

prepare-bloom10-review.mjs、prepare-bloom10-first-cut.mjs和verify-bloom10-first-cut.mjs是当前案例脚本，固定了源文件指纹、30.278秒、909帧、修订词位置、字幕与图形时点等信息。新视频需要新建对应配置或脚本，并注册新的Composition，不能只把新文件改成旧文件名后运行。

建议顺序为导入与规格检查、原文转录、人工校对、品牌适配、分镜审阅、必要效果样片、声音处理、整片渲染、自动检查和完整观看。每一步先汇报目的、结果与下一步计划，经你验收后再继续，沿用本次协作方式。

可以给编辑代理这样的任务说明：

“制作这段英语口播。先读取brand/BRAND.md和现有工程，检查新素材规格并转录。为新视频建立独立配置和Composition，不改写旧视频的时间戳和校对记录。每完成一步汇报并等待我确认，先给分镜，再做效果样片，最后输出整片与检查结果。”

## 十五 归档与常见问题

### 成片和工程分别保存

交付时保存MP4、修订SRT、版本说明和必要的检查记录。为了以后还能修改，还要保留src、scripts、brand、docs、package.json、package-lock.json、原始素材、字幕、效果和字体。

node_modules可以按锁文件重装；public/derived可以按脚本重建；bin/whisper.cpp中的程序和模型可按固定提交与校验值重建。原始素材和人工校对记录不应只依赖可再生成目录。当前还存在未提交代码，归档整个项目时不要只复制已提交文件。

| 问题 | 本次处理方法 |
| --- | --- |
| 工具已安装但命令找不到 | 重新打开终端，检查PATH和实际安装位置 |
| npm.ps1被阻止 | 使用npm.cmd与npx.cmd |
| Git无法首次提交 | 为当前仓库配置姓名和邮箱 |
| Whisper编译失败 | 确认MSVC C++工作负载与Windows SDK |
| 源码完整克隆过慢 | 改为浅克隆，并记录实际提交 |
| 模型直连超时 | 换可达镜像，按官方值校验完整性 |
| 相同文件名换了内容 | 归档旧结果，核对指纹，重新识别和审阅 |
| 英语产品词识别错 | 用small.en对照，保留原稿，记录人工修订 |
| 渲染耗时持续上升 | 使用工作画面帧，检查并发、缓存和本任务进程 |
| 字幕字数不多仍越界 | 按真实字体测量宽度，调整换行后重新导出 |
| 透明WebM叠加变黑 | 检查alpha及解码方式，使用transparent加载 |
| 短样片少一帧 | 对齐输入时间戳，验证实际帧数和尾帧处理 |
| 播放出现双人声 | 确认画面源静音，仅加载一次混合音轨 |

下一步要改变现有工程前，先检查当前素材、版本和审阅记录，避免把历史状态当成当前状态。根README中较早的分步文字是过程记录；本手册与当前输出报告用于理解现阶段完整流程。
