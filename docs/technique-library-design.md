# 剪辑技巧库与方案台设计（第二轮，讨论稿）

状态：第一批 12 张卡片和三种开场组合已确认（2026-10-29）。卡片格式和方案台的细化设计见 [storyboard-desk-design.md](storyboard-desk-design.md)。
依据：
- `skill/How_to_edit_videos_with_Claude_every_effect_from_my_video.pdf`（下文简称 PDF，共 14 个效果）；
- TikTok 带货短视频的常见剪法；
- 当前引擎能力：Phase 1 edit-plan、第一轮审阅台。

## 1. 完整流程

```
素材入库 → 方案（技巧组合）→ 补素材 → 审阅台 → 渲染质检
  ①            ②              ③          ④         ⑤
```

1. **素材入库**
   - 自动完成：转录、生成预览代理、人脸检测。
   - Claude 把口播切成"段落角色"：钩子、痛点、卖点、证明、用量、CTA，并标出哪些句子讲的是产品事实。
2. **方案**
   - Claude 从技巧库里挑选卡片，组合出 3 套方案。
   - 每套方案的开头钩子和整体风格不同，中段的卖点和 CTA 尽量共用。
   - 你选定一套，可以在风格菜单里替换样式。
3. **补素材**
   - 选定的方案会暴露缺少哪些素材。
   - Claude 先从原片里找能截取的帧，找不到的列进补拍清单。
4. **进入审阅台**
   - 素材齐全后，方案编译成 edit-plan v1，进入第一轮已经完成的审阅台。

素材和方案是交替进行的：先看现有素材能做什么方案，选定方案后再补素材。

## 2. 技巧卡片

一张卡片就是一个可以重复使用的剪辑技巧。卡片说明四件事：

- **什么时候用：** 触发条件；
- **需要什么素材：**
- **在 edit-plan 里生成什么：**
- **哪些规则不能违反：**

方案就是几张卡片的组合，所以 Claude 出方案时有依据，不是凭空发挥。

### 2.1 卡片格式

```jsonc
// library/techniques/benefit-checklist@1.json
{
  "id": "benefit-checklist@1",
  "name": "卖点打勾清单",
  "category": "benefit",                 // hook | caption | rhythm | benefit | proof | cta | transition | audio
  "status": "ready",                     // ready（引擎已支持）| needs-effect（要开发新效果）| needs-model（要新模型）| draft（刚从参考视频学来，待你确认）
  "source": ["tk-common"],               // 例如 "pdf#3"、"ref:tk-0007"（参考视频）、"tk-common"
  "description": "口播连续说出 2–4 个卖点时，屏幕上的清单逐条打勾出现，每条对应说出该卖点的那个词。",

  // 何时用：Claude 在转录里找匹配的段落
  "when": {
    "roles": ["benefit"],
    "transcript": "同一段里有 2–4 个并列卖点（名词短语）",
    "minDurationMs": 2500
  },

  // 需要的素材：缺了会进入补素材清单
  "needs": [],

  // 生成什么：edit-plan 片段模板，$ 开头的是 Claude 填的槽位
  "template": {
    "overlays": [
      {
        "effect": "check-list@1",
        "from": { "word": "$firstBenefitWord" },
        "until": { "segment": "$segment", "edge": "end" },
        "props": { "items": "$items", "x": 90, "y": 380, "width": 620 }
      }
    ]
  },

  // 可以在风格菜单里换的参数
  "tunables": {
    "props.y": { "label": "垂直位置", "range": [250, 1200] },
    "style": { "label": "样式", "options": ["white-card", "dark-glass"] }
  },

  // 审美和规则：方案编译和审阅台检查都会用到
  "rules": [
    "不遮挡人脸（覆盖不超过 10%）",
    "最多 4 条，每条不超过 18 个字符",
    "清单上的每一条都必须是 assets.json 里已核实的卖点"
  ],

  "examples": ["library/examples/benefit-checklist@1-a.jpg"],

  // 学习记录：每次用到都会更新
  "stats": { "proposed": 0, "selected": 0, "rejected": 0, "notes": [] }
}
```

卡片格式会用 zod 定义 schema，`plan:check` 也会校验卡片，做法和 edit-plan 一样。

### 2.2 风格包（全局）

字体、配色、字幕样式、转场风格、调色这类设置会影响整条视频，不按时间点出现，所以放在风格包里，不做成卡片：

```jsonc
// library/styles/clean-pink@1.json
{
  "id": "clean-pink@1",
  "name": "清爽粉",
  "fonts": ["Inter-700"],
  "palette": { "primary": "#ff7ab6", "text": "#101820", "card": "#ffffff" },
  "captions": "word-box@1",
  "transition": "whip-pan@1",
  "grade": { "brightness": 1.03, "contrast": 1.05, "saturate": 1.08 }
}
```

方案台的"风格菜单"就是替换风格包里的某一项。

### 3.3 三套方案的默认组合

| | 方案 A：痛点开场 | 方案 B：搜索框开场 | 方案 C：产品特写开场 |
| --- | --- | --- | --- |
| 钩子 | H1（痛点问句）+ R2 | H2 | R2 推近产品 + P3 |
| 中段 | 三套共用：R1、C1、P1、P2、P4、R3 | 同左 | 同左 |
| 结尾 | 三套共用：CTA1 + S1 | 同左 | 同左 |
| 风格包 | 清爽粉 | 深色质感 | 暖色生活感 |

这三种开场是带货视频最常见的写法。Claude 出方案时，会根据转录里实际有没有对应的句子来挑选：没有痛点句，就不出方案 A。

## 4. 第二批候选

- **文字在头后（PDF 2）：** 需要逐帧人像分割。
  - 可行做法：用已安装的 MediaPipe 加 selfie segmenter 模型（约 250 KB），在 Chrome 里离线逐帧生成遮罩。
  - 不需要 Python，也不需要 rembg。
  - 头发边缘的效果要先实测，你的显卡只有 2 GB 显存，这条路线主要靠 CPU。
- **对比分屏：** 只用于中性对比，例如"普通瓶装和独立包装"。不做疗效的前后对比。
- **评论回复贴纸：** 视频开头出现"回复某位用户的评论"样式的气泡，只能用真实评论。
- **从参考视频学来的新卡片：** 见 §5。

## 5. 持续学习

1. **从参考视频学：**
   - 你提供 TK 视频，可以是文件或链接。下载需要你确认，素材只用于分析。
   - Claude 做三件事：转录、按镜头切分、抽关键帧。然后逐段识别用了什么技巧，例如"0–2 秒 大字钩子，弹入，红色描边"。
   - 已有的技巧，记成该卡片的一个参考样例。
   - 新的技巧，生成一张 `status: draft` 的卡片，附上截图和时间点。
2. **你确认后才入库：**
   - 草稿卡片由你批准；
   - 需要开发新效果的，标为 `needs-effect`，进入开发排期。
3. **从审阅意见学：**
   - 你在审阅台拒绝提案时写的意见，Claude 会提炼成审美规则的候选，例如"CTA 标题必须一行"、"产品卡不能出现在右侧"。
   - 候选规则以提案的形式交给你批准，批准后写进 `library/taste-rules.json`。
   - 以后出方案和提案都会遵守这些规则，并在理由里写明引用了哪条。
4. **使用统计：** 每张卡片记录被提出、被选中、被拒绝的次数和原因，用来调整默认组合。

## 6. 文件结构

```
library/
├─ techniques/<id>@<v>.json     技巧卡片
├─ styles/<id>@<v>.json         风格包
├─ taste-rules.json             审美规则（每条记录来源：哪次意见、哪条提案）
├─ references/<ref-id>/         参考视频的分析结果（转录、镜头、关键帧、识别出的技巧）；原视频不入 Git
└─ examples/                    卡片示例图
projects/<id>/
├─ assets.json                  素材清单、补拍清单、产品事实核实
└─ storyboard/r1/               option-a|b|c.json、关键帧、selection.json
```

## 7. 合规与边界

这条视频的产品是保健品，需要特别注意：

- **产品事实：** 上屏的卖点和数字必须在 `assets.json` 的 `claims` 里标为已核实；依据可以选填。未核实的句子，Claude 会在方案里剪掉或不上屏。例如"30 天用量"目前还没有核实。
- **前后对比：** 不做疗效或身体效果的前后对比画面。
- **截图和评论：** 只用真实内容，并记录来源。
- **平台元素：** 不仿制 TikTok 的界面和标志。搜索框、购物车按钮都用通用样式。
- **他人内容：** 别人的视频只用于分析，不进入成片。音乐和音效只用有授权的。
