# 风格卡与风格库（v2）

一条剪得好的成品，拆成**一张风格卡**，存进**风格库**。出方案时选一张卡，「照卡」的那个创意方向直接取卡里的方向，并把这条成品的逐段剪法当作示范。

## 拆解流程（程序测量 + 模型标注 + 模型抽象）

1. 程序：每秒抽帧、找出每个硬切点、本地 Whisper 转写（词级时间）。
2. 模型 A：逐段标注——这一段是达人还是插画、全屏还是画中画、推近档位（z100/z110/z115/z120）、素材类型、这一段的作用（钩子、痛点、产品引入、演示、好处、证明、行动号召）。
3. 程序：根据标注算出**所有数字**（切点数、平均/中位镜头时长、最长不变画面、第一次插画时间、插画占比、全屏占比、画中画占比、推近变化频率）。数字不由模型估。
4. 模型 B：抽象成卡——方向、结构、技巧、给自动导演的规则、只属于这条视频的内容。
5. 程序检查：规则和结构里不能出现参考视频的产品名和产品功能（出现就打回重写）；方向取值必须合法；方向里的插画占比和节奏要和测出的数字一致（不一致程序自动改并提示）；规则最多 8 条；每个技巧要有出现的时间点作证据，没有就删掉。
6. 程序自测：用参考视频自己的口播，按这张卡出一次方案，和参考视频比，得到复现度。
7. 你核对、改名、确认。**确认了才能用于出方案**，改过已确认的卡要重新确认。

## 卡里有什么（`library/style-cards/<id>.json`，schemaVersion 2）

| 部分 | 内容 |
| --- | --- |
| meta | 产品类型、视频形式、语言、标签（出方案选卡时排序用） |
| measured | 程序测出的数字（只读，改时间线后自动重算） |
| direction | 开场处理、结构重心、节奏、插画位置、版式、推近方式、插画占比目标——和出方案的「创意方向」是同一套字段 |
| presetOverrides | 覆盖节奏预设的数字：全屏/画中画最早出现时间、镜头最短/最长、插画占比上限、画面最长不变 |
| structure | 通用角色分段（不出现产品名）和每段的剪法说明 |
| timeline | 参考视频逐段的示范方案：画面、版式、推近、素材类型、强调词、这一段发生了什么 |
| techniques | 用到的技巧，对应效果清单，标注已支持/部分支持/暂不支持，并给出现时间 |
| directorRules | 给自动导演的英文规则，最多 8 条，不含产品名 |
| contentSpecific_zh | 只属于参考视频产品的内容，只作参考，不交给自动导演 |
| captions / packaging_zh | 字幕和包装（贴纸、音效、音乐），只记录，不交给模型 |

旧格式（六栏）的卡仍然能打开，但会提示「重新拆解」；旧卡不会被删。

## 页面

- **概览**：方向的中文摘要、复现度、测出的数字、节奏数字、标签。
- **时间线**：结构条加关键帧，下面逐段可改。
- **规则**：给自动导演的规则、结构的剪法说明、只属于参考视频的内容。
- **技巧支持**：已支持、部分支持、暂不支持三组。
- **风格库首页**：按产品类型、视频形式、节奏筛选；「待开发的效果」汇总已确认卡里还做不到的技巧，用到的卡越多越靠前。

## 卡怎么影响出方案

选了一张已确认的 v2 卡时：

- 三个创意方向里，「照卡」的那一个直接用卡里的方向，另外两个在开场、节奏、结构上必须和它不同；
- 「照卡」那套的数字用卡里的 presetOverrides；
- 卡里的 timeline 作为示范方案放进「照卡」那套的提示词（只学节奏和结构，不抄内容）；
- 卡里的规则（英文）放进三套的提示词，当风格参考。

没选卡时，三个方向都按节奏预设。

## 已定的决定

- 时间线只有一份（cut-script），edit-plan 由它编译。
- 包装（贴纸、音效、音乐）只记录，不进渲染，也不做音效；需要的话在剪映里补。

## 片段库：从优秀视频学习，指导方案生成

这里的"学习"不是训练模型。每次调用的还是同一个模型 API，学习是指：**把优秀视频拆成一句一句的示例存起来，出方案时挑出最相关的，放进提示词。**

| 层次 | 存什么 | 出方案时怎么用 | 现状 |
| --- | --- | --- | --- |
| L1 整条风格 | 风格卡的方向、节奏数字、规则 | 决定"照卡"那一套的整体打法 | 已做 |
| L2 段落剪法 | 每种角色（钩子、痛点、好处…）怎么剪 | 卡里的结构说明 | 已做 |
| L3 逐句示例 | 参考视频里每一句是怎么剪的 | 给新口播每一句找最像的几句，当示范 | 已做（检索先用词语重合 + 句子特征，还没接文本向量） |
| L4 你的修改 | 你在精修里改过的地方 | 导出后，改过的、没改的每一句都写回片段库，改过的权重最高 | 已做；"常见修改总结成候选规则"还没做 |

**片段库**在 `library/segments/segments.jsonl`，每行一句：来源（参考视频 / 你精修过的 / 你没改直接用的）、角色、句子特征（开场带场景、提问、说出产品名、转折、功能、结果、情绪、数字、行动号召）、这一句怎么剪（达人还是插画、哪个词切插画、全屏还是画中画、素材类型、推近、强调词）。

- **风格卡确认时**，参考视频的每一句进片段库；卡改回草稿或删除，对应的句子就移出。
- **出方案时**：先给新口播每一句标角色和特征（一次模型调用，存在项目的 `analysis/line-labels.json`），再按"词语重合 50% + 特征重合 30% + 来源权重 20%"给每一句挑最多 3 条示例，同一个来源最多 1 条。"照卡"那一套只从所选卡的句子里挑，另外两套从整个库里挑。
- **创意方向**那一步还会看到"库里的整体倾向"（例如钩子 92% 是达人出镜），要求至少一个方向照着多数来、至少一个方向故意反着来。库里少于 8 句时不给倾向。
- **导出之后**（渲染成片，或生成剪映草稿），把审阅台里的最终版本和当初 AI 的方案逐句比较：改过推近或镜头的写成"你精修过的"，没改的写成"直接采用的"。AI 原方案在放进审阅台时存在方案的 `meta.aiPlan` 里。
- 命令行调试：`node scripts/auto-director.mjs <项目> --stage=plan --slot=a --show-examples` 会打印挑中的示例；加 `--no-examples` 就不用片段库，方便对比有没有它的差别。

库越大越有用：5–8 张卡、一百多句开始明显起作用；你自己精修过的成片积累到 20 条以上，会比只用参考视频更贴近你的审美。
